## 问题根因

`import_confirmation_results` 原先固定把工作表第 1 行作为字段表头。TASK-005A 原始“待确认地址清单”在真实表头上方包含标题、说明和空行，真实表头位于第 4 行，因此导入会误报全部字段缺失。

## 修复内容

- 导入时只读扫描第一个工作表的前 20 行。
- 仅将同时包含以下 8 个精确字段名的行识别为真实表头：
  - `地址ID`
  - `原始城市`
  - `原始详细地址`
  - `高德标准地址`
  - `定位层级`
  - `修正查询地址`
  - `是否确认`
  - `确认备注`
- 字段列顺序可变；字段名不做模糊、包含或同义词匹配，仅忽略单元格文本两端空白。
- 真实表头上方的合并标题、说明文字和空白行自动忽略。
- 识别表头后，数据从真实表头的下一行开始读取，错误信息保留原 Excel 行号。
- 不再依赖 openpyxl 的 `max_row`/`max_column` 尺寸元数据，可正确读取现有 TASK-005A 原始清单。

## 无法识别时的诊断

前 20 行中找不到完整表头时，导入摘要会显示：

- 实际扫描行数；
- 每行前 8 个非空单元格的列位置和截断内容；
- 与必需字段匹配数最多的可能表头行；
- 候选行的匹配数和缺少字段。

诊断内容只用于向当前用户说明导入格式问题，不写入地址库。

## 数据与业务保护

- 地址 ID 仅用于查找现有地址记录，不会被修改或重新生成。
- `原始城市` 和 `原始详细地址` 不会因导入而修改。
- 本任务未修改确认决策、修正地址处理、缓存失效或导入成功/跳过/失败计数规则。
- 本次开发、自动测试和原始清单兼容检查均未配置真实地理编码客户端，高德 API 调用数为 0。
