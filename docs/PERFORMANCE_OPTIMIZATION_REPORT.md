# TASK-007A 性能优化报告（V1.0 正式版）

TASK-007A 清理后提交：`a35b7a7e0b8958758e07f689d30ccb6f2448311a`

V1.0 正式提交：`4075063ff8c0425715bbedbf70b6ffc10dd4ca9e`

## 技术摘要

TASK-007A 已把输出目录权限检查、工作簿表头/字段检测和检测后的地址清单同步从 Qt 主线程移出。用户随后在实际电脑和实际业务文件中确认：选择输出目录和自动检测不再卡顿，同一文件第二次检测明显更快，Excel/WPS 保存与结果检查正常，因此批准把 RC2 的同一业务代码正式定版为 V1.0。

正式回归中，当前 281 行验收样表首次检测为 **58.77 ms**、缓存命中为 **17.85 ms**；2,000 行与 10,000 行合成表首次检测分别为 **230.10 ms** 和 **887.12 ms**，缓存命中分别为 **87.62 ms** 和 **484.44 ms**。本次只改变性能与交互实现，没有修改“非线路报价”筛选、高德 API 合同、路线/地理编码缓存、可信地址内容、结果列口径、Excel/WPS COM 保存或工作簿验证逻辑。

## 测量范围与指标定义

- “首次检测”指文件、大小、修改时间、工作表和算法版本尚无匹配缓存时，从开始只读打开到 `WorkbookInfo` 返回的墙钟耗时。
- “缓存命中”指同一文件签名和同一工作表再次检测的墙钟耗时。
- RC1 基线使用修改前代码在当前 828,799 字节、281 行验收样表上逐阶段实测。
- 正式回归环境为 Windows 11、Python 3.12.10、openpyxl 3.1.5；没有调用真实高德 API。
- 文件对话框停留时间取决于用户操作和 Windows Shell，不能用固定实验值代表。RC2 会在实机运行时记录“点击选择输入文件/输出目录”和“对话框返回”的实际时间。

## 方法改变：单次流式读取代替重复随机读取

工作簿检测使用 openpyxl 只读 OOXML 模式，不使用 Excel/WPS COM。检测只打开用户选择的工作表，表头候选限定在前 20 行；字段候选只使用表头及最多 30 行样例；预览只生成表头和前 10 行数据。城市目录只流式读取映射后的两列，最后使用列通过所选工作表 XML 的单元格引用计算，从而保持原有结果列规划口径，同时不读取图片、图表、宏、数据透视表或逐单元格样式。

所有 GUI 发起的工作簿检测都在独立 `QThread` 中执行。线程依次发送“正在读取工作表”“正在识别表头”“正在分析字段”“正在生成预览”；窗口移动、页签切换和 Qt 事件处理不依赖检测完成。

## 并发与取消：旧结果不能覆盖新文件

- 检测按钮在运行期间显示“检测中…”，同时提供“取消当前检测”。
- 相同文件、工作表和表头参数的重复请求会被拒绝，不创建第二个任务。
- 检测中重新选择文件时，旧任务收到取消标记，新任务排队；结果通过单调请求 ID 和当前规范路径双重校验。
- 已取消、已过期或属于旧文件的结果不会写入当前界面。
- 同一文件同一错误只弹出一个中文错误框；取消不弹错误框。
- 地址清单同步也在后台线程运行，避免检测完成后又在 GUI 线程读取整表或加载 SQLite。

专项 GUI 测试覆盖页签切换、快速连续检测、检测中更换文件、取消按钮和按钮忙碌/恢复状态。

## 输出目录：选择完成后立即恢复

输出目录对话框返回后，主线程只保存路径字符串、更新输入框和状态文字，再通过零延迟 Qt 事件把检查交给后台线程。后台检查不枚举目录内容，只检查目录类型并创建/删除一个唯一临时探针文件；等待上限为 3 秒，超时后 UI 显示明确状态。

| 输出目录场景 | 已有文件数 | 后台检查耗时 | 结果 |
|---|---:|---:|---|
| 空目录 | 0 | 19.24 ms | 可写 |
| 大量文件目录 | 1,000 | 2.99 ms | 可写，原有文件数不变 |
| 慢磁盘模拟 | 不适用 | 30 ms 测试上限 | 超时状态返回，UI 不等待模拟的 200 ms I/O |

选择输出目录的代码路径不调用工作簿分析、目录扫描、Office 检测、SQLite、可信地址库、路线缓存或结果文件生成。

## 检测缓存：文件变化后自动失效

缓存键包含：

- 文件规范路径；
- 文件大小；
- 最后修改时间（纳秒）；
- 工作表名称；
- 用户指定表头参数；
- 检测算法版本 `task-007a-ooxml-v1`。

缓存文件位于运行目录 `cache/workbook_detection`。缓存只保存表头、字段映射、结果列、工作表元数据和少量脱敏预览；不保存城市全集或完整业务行。专项测试确认原始测试地址不会出现在缓存 JSON 中，文件内容或修改时间变化后缓存自动失效。

## 分阶段性能日志可用于实机复核

运行时日志写入 `logs/performance_task007a.jsonl`，每行包含时间戳、操作、阶段、耗时、状态和线程 ID，不记录工作簿完整内容。覆盖阶段包括：

- 点击选择输入文件、文件对话框返回；
- 读取工作表列表、自动识别表头、生成字段候选、生成前 10 行预览；
- 点击选择输出目录、输出目录对话框返回、输出目录权限检查；
- Office 检测；
- SQLite 加载；
- 缓存查找、缓存写入、检测总计、取消/失败状态。

## 验证结果与稳健性检查

- 离线自动测试：`200 passed, 4 skipped`，15.52 秒；跳过项已通过显式启用的真实 Office 测试另行验证。
- 覆盖 281、2,000、10,000 行；表头第 1、4、15 行；中文路径；带空格路径。
- 覆盖空输出目录、1,000 文件目录、慢磁盘、后台检测切换页签、连续点击、检测中更换文件、缓存命中和文件变化失效。
- 测试通过补丁禁止 HTTP 和 `subprocess.Popen`，确认表头检测没有调用真实高德 API，也没有启动 Excel/WPS 进程。
- TASK-007A 性能专项测试：`11 passed`，覆盖输出目录后台检查、表头检测后台线程、页签切换、连续点击、检测中更换文件、取消、缓存命中和文件变化失效。
- 正式便携版在发布目录、另一中文路径和带空格路径均启动成功，主窗口最慢 1.563 秒出现。
- 正式目录与 ZIP 各 191 个文件，安全扫描 0 命中，五个运行目录为空。

## 用户验收与限制

自动测试证明 Qt 事件循环持续处理页签切换和后台结果；用户实机验收进一步确认实际 Windows 文件对话框、实际业务文件和 Office 保存流程没有重新出现卡顿。10,000 行合成文件由流式写入器生成，缺少标准工作表维度元数据，因此缓存命中仍需快速扫描所选工作表的单元格引用；484.44 ms 仍满足 1 秒目标，正常 Excel/WPS 文件通常会直接提供维度元数据。

如后续电脑仍出现明显等待，可保留 `logs/performance_task007a.jsonl`，用于区分 Windows 文件对话框、慢盘权限检查、OOXML 打开或字段分析阶段。V1.0 已正式定版，不继续开发 V1.1 或其他新功能。

正式 EXE 位于 `D:\AI project\非线路运距计算\release\非线路运距计算工具_V1.0\非线路运距计算工具.exe`，正式 ZIP 位于 `D:\AI project\非线路运距计算\release\非线路运距计算工具_V1.0_便携版.zip`。Windows 10 尚未专项实测，首次使用必须先用业务文件副本测试。
